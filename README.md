### 트러블슈팅

**"VLM이 칼을 못 읽는다" — 원인은 VLM이 아니었습니다**

흉기 이벤트를 VLM으로 재판독하는데 야외의 진짜 칼을 두 모델 다 놓쳤습니다(0/5, 1/5).
모델 체급을 31B까지 올려보고, 화면을 2배 확대해보고, 인물만 크롭해서 키워보고, 프롬프트를 반박형에서 중립형으로 바꿔봤는데 전부 그대로였습니다.
가설이 다 떨어져서 마지막으로 저장 파이프라인을 의심했습니다.
저장 시점에 칼 73~76%로 검출됐던 바로 그 스냅샷에 같은 탐지기를 다시 돌렸더니 칼이 하나도 안 잡혔습니다.
스냅샷을 960x540으로 줄이고 JPEG로 압축하는 과정에서 칼 픽셀이 날아가고 있었습니다. 사람은 크니까 남고요.
VLM이 못 읽은 게 아니라 읽을 게 안 남아 있었던 겁니다. 그래서 확대하든 크롭하든 소용이 없었습니다.

해결은 원본 녹화본(1280x720)에서 프레임을 되찾는 거였는데, 여기서도 두 번 틀렸습니다.
이벤트 시각으로 한 장 뽑으니 0/4, ±3초를 2fps로 훑으니 2/4.
알고 보니 세그먼트 파일명의 HHMM이 시작 '분'일 뿐이고 키프레임 경계에서 잘려 실제 길이가 42~67초로 제각각이었습니다.
파일 수정시각에서 길이를 빼서 진짜 시작 시각을 구하는 걸로 고치니 6/6이 됐습니다.
저장 용량도 토큰 비용도 안 늘고, 기존 분석기는 한 줄도 안 고쳤습니다.

**mAP 0.98짜리 모델의 라이브 재현율이 31%**

걷기/서기 통합 모델을 배포했는데 서 있는 사람 판정이 무너졌습니다.
학습 점수는 좋은데 현장만 가면 안 되길래 데이터를 다시 봤더니, 학습셋과 평가셋이 같은 영상에서 몇 초 간격으로 자른 연속 프레임이었습니다.
사실상 같은 장면으로 공부하고 같은 장면으로 채점한 거라 그동안의 점수가 전부 의미가 없었습니다.
후처리 파라미터를 만지는 걸로 덮어보다가 한계가 와서 구조를 다시 봤는데,
최종 판정은 이미 박스 이동량이 하고 있었고 전용 모델은 사람 박스만 공급하고 있었습니다.
그 일을 더 잘하는 모델이 같은 프레임을 이미 처리하고 있어서 전용 모델을 지웠습니다.
나중에 재보니 기존 모델이 사람 박스 226개를 잡을 때 전용 모델은 71개만 잡고 있었고, 창가에 서 있는 사람 157박스를 통째로 놓치고 있었습니다.

**검증 정확도 100%인데 실사용에서 90%를 놓침**

사람을 잘라내 자세로 분류하는 방식을 세 구조로 시도했는데 전부 학습 장면에서만 잘 됐습니다.
클래스별로 촬영 환경이 갈려 있어서 모델이 자세가 아니라 실내/야외를 학습한 거였고, 검증셋도 같은 편향을 공유해서 100%가 나온 거였습니다.
여기서 사진 한 장에는 걷는 중인지 서 있는 건지 구분할 정보가 애초에 없다는 걸 확인했고, 그 뒤로 방향을 이동량 기반으로 바꿨습니다.
데이터를 더 모으거나 모델을 키워서 될 문제가 아니었습니다.
